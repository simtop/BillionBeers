# Android release evidence

Audit date: 2026-09-23

This record separates executed Android evidence from checks that require a physical device,
release credentials, external distribution, or manual QA. A green Gradle task is not treated as
proof beyond the behavior it actually exercises.

### Screenshot inventory

`make screenshot-verify` writes an executed preview inventory to
`build/reports/paparazzi/inventory/`. The audit produced eight module TSV files and 275 rows:

- `com_simtop_billionbeers_core_designsystem.tsv`: 42
- `com_simtop_billionbeers_t71_screenshot.tsv`: 1
- `com_simtop_feature_beerbrowse.tsv`: 84
- `com_simtop_feature_beerdetail.tsv`: 40
- `com_simtop_feature_beersearch.tsv`: 46
- `com_simtop_feature_beerslist.tsv`: 50
- `com_simtop_feature_favorites.tsv`: 2
- `com_simtop_presentation_utils.tsv`: 10

The rows have no duplicate `(module, snapshot)` IDs. The 1,102 checked golden PNGs represent the
four rendered variants for the 275 inventory entries. The inventory is generated by the executed
Parameterized Paparazzi runners, not inferred from source declarations.

The wrapper passes an absolute inventory directory because Gradle runs each module's unit test
with that module as its working directory. The screenshot convention declares the inventory
property as a test input so changing the output location cannot leave the test task up-to-date.

### Managed-device evidence

`make ui-test-managed` completed against the repository's managed-device lane. The checked lane is
`atdApi35` (Pixel 6, `google_atd`). Reports are under:

- `app/build/reports/androidTests/managedDevice/debug/atdApi35/`
- `app/build/outputs/managed_device_android_test_additional_output/debug/`

This proves the selected managed emulator configuration and its instrumented tests. It does not
prove behavior on every physical device, OEM image, API level, or form factor.

The verifier wrote `app/build/outputs/release-smoke/manifest.txt`, including SHA-256 hashes and

`releaseSmoke` variant. The smoke tests cover the local deterministic API, mapped catalog/detail
behavior, dynamic-feature navigation, availability mutation, Room persistence after process kill,
and back navigation.

This is minified local runtime evidence. It is not signing, Play upload, install-from-Play,
rollback, upgrade, or store-review evidence.

## Dependency verification boundary

`make dependency-guard` passed. The repository's dependency-verification metadata and reference
checks were inspected through the existing `verification-metadata-reference` path and CI workflow.
Linux CI remains the complete artifact-coverage lane for regenerating/verifying metadata; a local
macOS metadata check is not treated as a substitute for that platform coverage.

## Remaining checks

These checks were intentionally not claimed as completed by this audit:

- physical Android devices, OEM-specific behavior, and broad API/device matrix coverage;
- TalkBack, hardware keyboard/IME, reduced-motion and manual accessibility QA;
- manual compact-phone, tablet/foldable and font-scale release review;
- signing, Play/App Bundle delivery, staged rollout, upgrade and rollback behavior;
- a clean CI runner's exact SDK/JDK/toolchain environment;
- any release property not exercised by the managed device or minified smoke tests.

The manual accessibility procedure is maintained in
[`accessibility-release-qa.md`](accessibility-release-qa.md). These gaps keep Android's claim
bounded while leaving it as the primary released target.
